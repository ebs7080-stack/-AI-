# requirements.md

## 1. 프로젝트 개요

**프로젝트명(가칭):** 코드 웹 분석 도구 (Code Web Analyzer)

**목적:**
중·고등학교 파이썬 프로그래밍 수업에서, 수업을 잘 따라가는 학생과 어려움을 겪는 학생을 매칭하여 서로 돕게 하고, 학생이 작성한 코드를 정적 분석하여 단계적 힌트를 제공하며, 교사에게는 학생들이 공통적으로 어려워하는 부분을 통계로 제공하는 웹 서비스.

**핵심 가치:**
- 정답(전체 코드)을 바로 주지 않고, 단계적 힌트로 학생이 스스로 문제를 해결하도록 유도
- 또래 학습(peer learning)을 우선하되, 또래가 부족하거나 막힐 경우 LLM이 보조/대체
- 학생들의 어려움을 데이터로 축적해 교사의 수업 개선에 활용

---

## 2. 사용자 페르소나 및 시나리오

### 2.1 학생 A (수업을 잘 따라오는 학생)
- 별도의 코드 분석 도구가 필요하지 않음 (본인 코드 제출/분석 흐름은 선택적)
- 학생 B와 매칭되어, B의 코드를 이해하고 고치는 것을 도와주는 과정에서 스스로 복습 효과를 얻음
- 시스템이 제공하는 "단계적 힌트"를 참고하여 B에게 설명

### 2.2 학생 B (수업을 잘 따라오지 못하는 학생)
- 작성한 코드를 시스템에 입력(제출)
- 시스템이 코드를 정적 분석하여 오류/이해 부족 지점을 단계적으로 정리
- 매칭된 학생 A와 채팅으로 대화하며 코드를 스스로 수정
- 학생 A가 부족하거나 매칭이 어려운 경우, LLM이 A의 역할을 대신 수행

### 2.3 교사 C
- 여러 학생의 제출 코드와 오류 유형을 통계적으로 확인
- 학급/차시별로 학생들이 공통적으로 어려워한 개념·오류 유형을 파악하여 수업에 반영

## 3. 기능 요구사항

### 3.1 코드 분석 및 단계적 피드백
- **FR-1.1 코드 제출:** 학생 B가 작성 중이거나 완성한 파이썬 코드를 업로드/붙여넣기로 제출
- **FR-1.2 정적 분석:** 제출된 코드를 정적 분석(문법 오류, 논리적 의심 지점, 스타일 이슈 등) 수행
- **FR-1.3 오류 유형 분류:** 분석 결과를 사전 정의된 오류 유형(예: 문법 오류, 들여쓰기, 조건문/반복문 로직 오류, 자료형 오류, 인덱스 오류 등)으로 분류
- **FR-1.4 단계적 피드백 생성:** 정답을 바로 노출하지 않고, "관찰 → 의심 지점 → 힌트 → (필요 시 추가 힌트)" 순의 단계적 피드백을 준비
- **FR-1.5 피드백 노출 제어:** 학생이 한 단계씩 힌트를 요청해야 다음 단계 힌트가 공개됨 (자동 전체 공개 금지)

### 3.2 학생 매칭 및 협업
- **FR-2.1 매칭:** 도움이 필요한 학생 B를 도와줄 수 있는 학생 A와 매칭 (매칭 기준: 동시 접속 여부, 과목/단원, 난이도 등 — 상세 기준은 추후 정의)
- **FR-2.2 LLM 대체 매칭:** 매칭 가능한 학생 A가 부족할 경우, LLM이 학생 A 역할을 수행하여 동일한 상호작용 제공
- **FR-2.3 채팅:**
  - 매칭된 두 학생(또는 학생-LLM) 간 실시간 채팅 제공
  - **정답 코드 전체 붙여넣기(직접적인 해답 제공) 차단/필터링 기능** — 코드 블록 형태로 전체 정답을 그대로 전달하는 것을 감지하여 제한
- **FR-2.4 단계적 힌트 동시 제공:** B의 코드 분석 결과를 바탕으로 만든 단계적 힌트를 A와 B 양쪽에 동시에 제공하여, A는 이를 참고해 B를 지도
- **FR-2.5 추가 도움 요청(에스컬레이션):** 매칭된 학생 A가 문제를 해결하지 못하거나 어려움을 느낄 경우, 추가 도움(다른 학생 A, 교사, 또는 LLM)을 요청하는 기능

### 3.3 학습 통계 및 데이터 축적
- **FR-3.1 어려움 지점 기록:** 학생별 제출 코드와 분석 결과를 바탕으로 어떤 개념/유형에서 어려움을 겪었는지 기록
- **FR-3.2 케이스별 통계 분석:** 오류 유형별/개념별로 학생들의 어려움을 집계하여 케이스 단위로 저장
- **FR-3.3 교사 통계 제공:** 교사가 학급/기간/단원별로 학생들이 공통적으로 어려워한 부분을 통계(빈도, 추이 등)로 조회할 수 있는 기능

## 5. 비기능 요구사항 (초안)

- **NFR-1 안전성/교육적 가치:** 정답 코드 직접 노출을 막는 것이 핵심 정책이며, 우회 방법(예: 변수명만 바꿔 붙여넣기, 이미지로 코드 전달 등)에 대한 대응 방안 필요
- **NFR-2 확장성:** 향후 다른 언어(예: 자바 등) 지원 가능성 고려 (1차 목표는 파이썬)
- **NFR-3 데이터 프라이버시:** 미성년자(중·고등학생) 데이터를 다루므로 개인정보 보호 및 접근 권한 관리 필요
- **NFR-4 응답 속도:** 정적 분석 및 LLM 응답이 수업 시간 내 상호작용에 지장 없는 수준의 속도로 제공되어야 함

## 7. 용어 정리

- **학생 A:** 프로그래밍 수업을 잘 따라오는 학생, 도움을 주는 역할
- **학생 B:** 프로그래밍 수업을 잘 따라오지 못하는 학생, 도움을 받는 역할
- **교사 C:** 수업을 진행하고 학생 통계를 확인하는 역할
- **단계적 힌트(Progressive Hint):** 정답을 바로 주지 않고 단계별로 공개되는 힌트
